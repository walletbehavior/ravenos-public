# RavenOS Conversion and Monetization Audit

Last updated: June 2026

## Objective

Design the path from visitor to user to Pro to Desk without weakening the free product or overstating evidence.

## Current Read

RavenOS is strongest when it shows a complete trust loop:

Brief -> Opportunity -> Replay -> Outcomes -> Memory -> Behavior -> Terminal

The product becomes easier to trust when every read answers:

- What is happening?
- Why does Raven believe it?
- How fresh is the read?
- How much evidence supports it?
- What could weaken it?

## Free Tier

Free should prove the product quickly.

Recommended free value:

- Any-token lookup
- Basic chart
- Basic overlays
- Public coverage badge
- Basic structure summary
- Opportunity preview
- Daily Brief
- Limited Replay summary
- Limited Outcome Dashboard
- Limited Behavior Explorer

Free should not feel useless. It should show that Raven has a different way of reading markets.

## Pro Tier

Pro should unlock depth and workflow continuity.

Recommended Pro value:

- Full Opportunity Board
- Full Replay Lab
- Full Outcome Dashboard
- Full Market Memory
- Full Behavior Explorer
- Full Structure Lab
- Full Perps Intelligence
- Alerts
- Watchlists
- Saved research workflows
- Expanded overlays and explanations

The strongest Pro conversion moments are:

- User clicks a strong Opportunity cell and wants the supporting analogs.
- User sees a Replay summary and wants the full outcome breakdown.
- User wants alerts on structure changes rather than price levels.
- User wants watchlists that track pressure, participation, replay, and coverage changes.

## Desk / Atlas Tier

Desk or Atlas should be positioned as high-level context and research infrastructure.

Recommended Desk / Atlas value:

- Market regime layer
- Liquidity regime
- Cross-asset context
- Institutional context
- Deeper historical memory
- Expanded outcome database
- Exportable reports
- Team/research workflows

Atlas should not be sold primarily as more crypto widgets. It should answer: “What environment are we operating in?”

## Conversion Risks

### High: Evidence not visible enough

If users see precise scores without contributors, sample depth, and freshness, the scores feel like branded opinions.

Fix: keep Evidence, Score Transparency, and Why It Matters near every major read.

### High: Sample states look like product failure

Empty panels and stale labels reduce trust if not explained.

Fix: use “sample forming,” “delayed context,” and “last verified public artifact” where accurate, with clear freshness.

### Medium: Navigation breadth

Terminal, Opportunity, Replay, Outcomes, Memory, Behavior, Research, Perps, Atlas, Alerts, and Watchlists can feel broad.

Fix: keep the trust-loop journey explicit and make Terminal the active workspace rather than the only entry point.

### Medium: Paid pricing before visible validation

Professional pricing needs visible validation and outcomes.

Fix: keep Daily Brief, Opportunity, Replay, and Outcomes tightly linked so users can evaluate Raven’s reads over time.

## Recommended Product Path

1. Open Brief
2. Inspect Opportunity
3. Open Replay on a specific read
4. Check Outcomes for recent validation
5. Use Memory and Behavior for context
6. Open Terminal for instrument-level work
7. Save to Watchlist or create Alert
8. Upgrade when the user needs full replay, alerts, watchlists, and perps depth

## Pricing Recommendation

Keep current Pro pricing visible, but emphasize that Pro buys workflow depth, research history, alerts, replay detail, and perps intelligence.

Avoid return language. Do not imply Raven guarantees outcomes.
