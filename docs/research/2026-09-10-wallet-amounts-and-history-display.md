# Wallet amounts and history display

The live Base profile exposed an incorrect activity label: decoded payments and receipts were all given a default “unresolved non-settlement basis” label. A transaction's payment or sale proceeds are not a matched-inventory profit result. Reviewing the delivery contract also found that its explicit currency allowlist omitted supported Ethereum USDT, Binance-Peg USDT and Binance-Peg USDC. Valid recorded amounts could disappear when the private stored profile was projected for the browser.

The candidate preserves those three existing settlement units through period totals, token results and currency labels, without combining them with USDC or assuming a dollar value. Decoder and inventory requirements are unchanged. Receipt-to-public-response tests reproduce the missing USDT results, then verify both matched profits and unknown costs retain their original values. A separate registry test covers every settlement unit supported on all four EVM chains, while private fields remain excluded.

Activity cards show payments and receipts without an internal basis-state label. A short explanation points to the overview for profit based on matched purchase cost. Positive amounts below six decimal places no longer truncate to zero; integer arithmetic retains the available token precision. Missing decimals remain unavailable rather than becoming an assumed zero-decimal token. Buy and Sell labels are shortened and the two amount columns use the card width.

History loading is indeterminate because Raven does not know a wallet's total transaction count. The old calculation divided loaded references by the collection ceiling and could imply false completion, including 100% for a bounded partial history. Pending jobs now show loading or delay wording; processed and bounded windows hide the loading bar and state their limits. The overview also states when more activity is pending. Refreshing history status continues to use the retained profile endpoint and does not trigger another provider inspection. Unknown purchase costs stay excluded from profit.

Four backend regression failures were reproduced before correction. The final targeted backend selection passes 139 cases. Test fixtures were corrected to use actual amount formatting, exact source identity and immutable event insertion. All 79 wallet cases pass in each of Chromium and WebKit: the complete initial runs passed 78 each, and the remaining retained-page assertion was updated from “Swap Sell” to the shortened “Sell” label and passed on recheck. Both engines also pass three final cases covering mobile amount precision, honest history status and the styled Terminal overlay. The mobile visual review increased amount readability and gave Refresh history status an explicit theme style. Build, security, public-asset checks and all 41 Worker-response checks pass. Production deployment and signed-in postflight follow.

This work does not create new trades, prove new qualified wallets, activate public wallet groups, or satisfy the real-settlement gates. The 10–50-member category requirement, production rotation, complete usable histories and the final tab-by-tab audit remain open.
