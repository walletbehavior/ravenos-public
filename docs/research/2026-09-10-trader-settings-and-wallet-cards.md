# Trader settings and wallet discovery

User steering on 10 September extends roadmap packages 1, 2, 3 and 6. Finish the already deployed Reads/pagination postflight, then implement and verify these requirements. The parent roadmap remains active.

- Editable quick-buy amounts and quick-sell percentages directly accessible from the Terminal ticket. Keep chart/tape context visible while editing in a compact drawer.
- Named, reusable multi-leg take-profit/stop-loss profiles shared by Terminal and Copy. Every rule specifies a return trigger and position allocation. Validate per-side allocation totals, preserve the remaining position after partial exits, and never execute the same leg twice.
- Save profiles to the authenticated account with revision checks; apply an explicit version to each mirrored wallet. Editing a library profile must not silently change existing wallet policies or activate execution.
- Expose slippage and entry-order controls within the same screen. Preserve the 3% default and >5% slippage/impact warnings. Do not label saved plans or quote reviews as armed protective orders.
- Increase usable categorized EVM wallet coverage with the existing providers and budgets. Measure observed, profiled and category-qualified counts independently; repair intake/history/classification gaps instead of treating source labels as verified performance.
- Use compact wallet cards with current activity age, holding duration, trades, win rate/PnL where evidence permits, a wallet-profile drilldown, and a direct Copy setup action. Old performance must retain its observation window/age.
- Use the full internal profile engine across Solana and EVM: lineage, funding lineage, behavior, timestamped trades, timing, PnL and the other existing classifications. Early participation before large moves and cohort-family leads over KOL purchases are examples, not an exhaustive list or a replacement taxonomy.
- Proprietary fields stay server-side: internal labels, relationship/lineage edges, thresholds, scores, rule details and supporting data points must not reach the browser. Public cards and profile groups expose only plain-language, honest, defensible summaries and appropriate freshness/confidence. Internal qualification still requires identity, causal timestamps and support for each claim; a simplified presentation must not imply unverified performance or current relevance.

The current Copy engine is shadow plus manual trade review. Live order activation, real-money tests, signatures and independent autonomous execution still require the existing specific authority and validation gates. Building settings and policy support does not activate them.

Additional requested category: **Patient top holders**. Internally require repeated high holder rankings across timestamped positions and an average hold strictly greater than four hours. Make the holder band configurable; top decile is the initial proposal only where a reliable full distribution exists. A single large balance, truncated top-N list, missing denominator or current token snapshot does not establish usual percentile rank. The customer-facing category and short summary must not disclose the thresholds, observation counts or private supporting records. Await Core admission and current eligible counts before calling this list populated.
