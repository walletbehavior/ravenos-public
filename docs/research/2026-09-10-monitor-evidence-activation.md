# Monitor evidence and in-app activation

The live audit found alerts disabled. Inspection also found that the editor offered every event type regardless of evidence, the loader returned early for every onchain market, and the evaluator ignored Pro access supplied by current trials/subscriptions. Six database cases reproduced access, pause/revision and notification-binding failures before correction.

## Changes

- Read-only, account-owned `/api/v1/monitor-alerts/evidence/:watch_id` exposes the exact market's supported changes and observation time. The editor loads these choices when opened; unavailable or mismatched evidence leaves creation disabled with a reload action. No personal rule is created by opening it.
- The onchain loader reads the existing shared participation snapshot once per batch. Fresh, exact DexScreener pool observations can establish snapshot availability and one-hour buy/sell transaction-count pressure. At least ten measured transactions are required; 60% buy share is buy-led, 40% or less is sell-led, and the middle is balanced. Missing counts never become zero, and retained/stale/missing rows never establish delisting. No new market-provider requests are introduced.
- Solana, Base, Ethereum, BNB and Robinhood identities remain separate. Token/quote/pool mismatches, unsupported chains, future observations and conflicting same-time evidence are rejected. This does not qualify the experimental Discovery classifier or infer lifecycle, wallet profit, net dollar flow, route liquidity or execution readiness.
- Evaluation matches current trial and funded subscription windows as well as manual grants. Account state, rule state/revision and access are checked again when persisting. Notifications and their comparison baseline commit atomically, so a database failure can retry the undelivered transition. Duplicate protection, quotas and cooldowns remain. Measurement-version changes start a new baseline; separately qualified exact availability changes remain usable.
- The existing package activation controls enable in-app alerts for entitled accounts; runtime defaults and independent overrides remain. No outbound delivery channel or personal alert rule is activated by this work. No plan, payment, trade or signature is created.
- Mobile editor choices use 14px text and at least 44px targets.

## Preflight source failure and collector correction

The 10 September 10:52:13 UTC read-only production probe found 4,365 retained markets but zero observations within two minutes on all five chains (2,424 Solana, 87 Base, 104 Ethereum, 786 BNB, 964 Robinhood). The newly assembled snapshot timestamp did not establish fresh market observations. At 10:53:55 UTC the newest observation was already 388 seconds old, the median 989 seconds and the oldest 13,529 seconds. Collection recorded four upstream HTTP 429 responses followed by 61 locally rejected attempts. Existing personal rules and notifications were both zero. The candidate `c12857db08c1` was packaged but not staged or promoted.

Three regression cases reproduced independent failures before correction: a cold provider reader lost a prior instance's cooldown; the collector continued scheduling the remaining batch and could restart before the shared retry deadline; and alert evidence rejected compacted collector rows because the collector intentionally removed their duplicated provenance object. The corrected reader shares bounded cooldown records through the existing public edge cache, keeps local protection if that cache fails, and preserves separate endpoint scopes. The collector stops scheduling after a shared rate/quota/service cooldown, permits already in-flight requests to finish, and persists the retry deadline with its existing snapshot lease. Original observation timestamps remain unchanged. Evidence accepts the collector's explicit source identity while rejecting conflicting provenance when present.

This adds no provider budget or retry bypass. Edge caching is local to a serving location and best effort; it is not a global atomic request budget. The initial cause of the provider's 429 is not yet established. The repeatable probe now records actual observation ages, failed batches and the persisted retry deadline so production recovery can be checked after deployment. Stale rows remain ineligible for new onchain alert evidence.

The corrected candidate passes 119 targeted market/participation/Monitor/security/release cases, including a real workerd cache and compressed D1 round trip. That runtime fixture was updated to include the existing frontier migration; no production migration is added. Build/security and all 40 public-response checks pass. Earlier Chromium/WebKit editor qualification remains applicable because this correction does not change the editor.
