# Wallet totals lost when transfer metadata was missing

A signed-in BNB inspection displayed retained USDT buys and sells in its activity, while the overview had no reconstructed totals. The same wallet's frozen 474-event record reproduces zero trades with the deployed implementation. Exactly one transfer lacks token decimals among otherwise consistent observations of the traded contract. Treating that missing metadata as a conflicting precision caused every trade of the token to be excluded.

The correction keeps transfer inventory in its exact recorded integer units and uses a consistent known scale for the same contract. It does not treat absent metadata as a disagreement. Conflicting or malformed declared precision, malformed integer amounts and tokens with no known scale still remain excluded. A trade continues to require its own event precision; another event's metadata cannot turn it into a verified acquisition. Incoming transfers retain unknown cost, outgoing transfers consume inventory, and incomplete opening balances continue to prevent unsupported profit.

The immutable input replay now produces 106 buys and 159 sells through the actual profile builder and public projection. Recorded purchase payments total `20079.082144926315120445` Binance-Peg USDT and sale receipts total `20027.101945812774646861` in that same unit. These are not profit: all matched-profit values remain unavailable, with zero fully matched sells. No input event, Copy eligibility, provider data or production record was modified by the replay. Its input SHA-256 is `be8fa243aa0c4860ef10bc0b5e92d20e0a7e9217d6c4c5fb019540df869e07d4`; raw replay input stays outside the public repository.

Analytical profile version 4 makes existing Ethereum, BNB, Base and Robinhood profiles eligible for one rebuild through the existing bounded queue. The queue does not repeat an upgrade once its version is current. It does not raise provider ceilings, reset history jobs, change execution authority or add a migration.

Six regression failures were reproduced before correction. The 173-case backend selection passed 172 on its first corrected run; the remaining new test mistakenly asserted an intentionally omitted public field. It now checks the supported public observation count and the retained full-match count separately, and all ten settlement cases pass on recheck. Coverage includes incoming/outgoing transfers, partial sells, zero-decimal tokens, malformed/conflicting precision, preservation of original events, separate settlement units and one-time refresh on all four EVM chains.

The initial correction, source `79e8a166085598322847800b5e54ad5e1e31b9d3`, deployed as `ravenos-79e8a1660855-121b64d302d7efa5`, Worker `a42c2a8b-fd78-4dd6-b161-f1cd8ab84487`. Build/security checks and all 66 production release checks passed. The first staging attempt stopped at the health gate; after the exact staged Worker reported healthy, the same uploaded version passed the full verification and was promoted. No health requirement was changed or bypassed.

Production postflight then found a second defect: version-based refresh checked only the small inline profile record. The BNB sample's 68,417-character full record is retained separately, and its 1,167-character inline projection omitted the reconstruction version. The upgrade queue therefore missed it. Eleven other profiles had reached version 4, while this sample remained version 3. That did not count as successful delivery of the fix to the sampled wallet.

The follow-up reads retained details only for older EVM profiles whose inline record lacks the required version. New large snapshots keep that one version marker inline; detailed inventory stays in its existing immutable record. No old snapshot is rewritten. Two additional storage/queue regressions were reproduced, then all 184 targeted backend cases passed, including legacy large profiles, current-version exclusion, missing reconstruction evidence, append-only preservation and full record round trips. Follow-up deployment and the sampled wallet's live rebuild remain to be verified.

This fixes the lost trade totals, not the remaining depth or cost-basis gaps. Qualified wallet categories still need 10–50 current members, measured rotation and the private source publisher. The remaining roadmap packages and final desktop/mobile audit remain open.
